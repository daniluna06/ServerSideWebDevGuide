Shopping Carts & E-Commerce

Electronic commerce (e-commerce) is more than just "add to cart" buttons. It involves:

  • Online shopping (retail to consumer) and marketplaces
  • Electronic funds transfer and payment processing
  • Inventory management and order tracking
  • Internet marketing and data collection

The Developer Perspective

From the developer's point of view, an e-commerce site typically includes:

  • The product database (tables for products/images, prices, details, etc.).
  • Admin tools for:
    • Adding products.
    • Editing or deleting products.
    • Completing orders or updating order status.
  • Public-facing pages for:
    • Listing products (catalog view).
    • Showing product details for one item.
    • Creating and managing a shopping cart.
    • Checking inventory and storing orders.

Admin Side: Product List & Details

On the admin side, a secure login protects a menu that includes links for things like:

  • Add a product (add a new image/print).
  • View or complete an order.

On the public side, users see:

  • product_list.php - queries the database and displays a list (or gallery) of products.
  • Next to each product, a View Details button or link.

The "View Details" button is usually an HTML form with a hidden field for the product's primary key (like image_id): 

<form action="cart.php" method="get">
    <input type="hidden" name="action" value="details">
    <input type="hidden" name="image_id" value="<?php echo $row['image_id']; ?>">
    <input type="submit" value="View Details">
</form>

Because this form is inside a loop, each product row gets its own button, and the hidden image_id value matches that specific image.

On product_details.php, you retrieve that ID with $_GET and query the database to show the full info for that product.

The Shopping Cart in $_SESSION

Once the catalog is in place, the shopping cart lives in sessions: $_SESSION['cart']

The cart is a multi-dimensional array where each key is an $imgID, and the value is another array with details: 

$_SESSION['cart'][$imgID]['caption']  // print caption
$_SESSION['cart'][$imgID]['quantity'] // quantity ordered
$_SESSION['cart'][$imgID]['price']    // price of one item

Conceptually, it looks like this:

$_SESSION['cart'] = [
    2 => [ 'caption' => 'Fountains in central Tokyo',
           'quantity' => 1,
           'price'   => 59.99 ],
    3 => [ 'caption' => 'The Golden Pavilion in Kyoto',
           'quantity' => 2,
           'price'   => 9.99 ]
];

If you wanted, you could nest this under a user ID (for example, $_SESSION['userid']['cart']), but JJ keeps it at $_SESSION['cart'].

cart.php - Central Cart Controller

The file cart.php is the controller for the shopping cart. It:

  • Starts the session and initializes $_SESSION['cart'] if it doesn't exist.
  • Determines what action to take based on $_GET['action'] or $_POST['action'].
  • Performs that action (add/update/show/empty) and then includes cart_view.php as needed.

In your JJ code, the valid actions are:

  • 'details' - show product_details.php.
  • 'add' - add an item to the cart.
  • 'update' - update quantities in the cart.
  • 'show_cart' - just display the cart.
  • 'empty_cart' - clear the cart from the session.

Typical pattern at the top of cart.php:

// Start session and ensure cart exists
session_start();
if (!isset($_SESSION['cart'])) {
    $_SESSION['cart'] = [];
}

// Determine action
if (isset($_GET['action'])) {
    $action = $_GET['action'];
} elseif (isset($_POST['action'])) {
    $action = $_POST['action'];
} else {
    $action = 'show_add_item'; // default
}

Then a switch statement uses $action to decide what to do.

Adding Items to the Cart (Action: add)

When the user clicks Add to Cart on product_details.php, a form posts data like:

  • image_id
  • quantity
  • action = "add"

In cart.php, the 'add' action:

  1. Sanitizes the posted image_id and quantity.
  2. Checks if the item is already in the cart:
    • If yes → just bump up the quantity.
    • If no → look up the image in the JJ_images table and add a new cart row.
  3. Includes cart_view.php to show the updated cart.
$imgID = filter_var($_POST['image_id'], FILTER_SANITIZE_NUMBER_INT);
$qty   = filter_var($_POST['quantity'], FILTER_SANITIZE_NUMBER_INT);

if (isset($_SESSION['cart'][$imgID])) {
    // Already in cart - just update quantity
    $_SESSION['cart'][$imgID]['quantity'] += $qty;
} else {
    // New item - look it up in JJ_images
    require_once '../../pdo_connect.php';
    $getImage = "SELECT * FROM JJ_images WHERE image_id = ?";
    $stmt     = $dbc->prepare($getImage);
    $stmt->bindParam(1, $imgID);
    $stmt->execute();

    if ($stmt->rowCount() == 1) {
        $item     = $stmt->fetch();
        $imgTitle = $item['caption'];
        $imgPrice = $item['price'];

        $_SESSION['cart'][$imgID]['caption']  = $imgTitle;
        $_SESSION['cart'][$imgID]['quantity'] = $qty;
        $_SESSION['cart'][$imgID]['price']    = $imgPrice;
    } else {
        // handle invalid ID
    }
}

Updating Quantities & Emptying the Cart

The update action happens when the user submits the cart form on cart_view.php after changing quantities.

Each quantity input is named newqty[imgID], so when the form is submitted you get an array: 

$_POST['newqty'] = [
    2 => 1,
    3 => 0,
    5 => 4
];

In cart.php, the 'update' case loops over this array:

  • If a quantity is 0 or less → remove that item from the cart.
  • Otherwise → update $_SESSION['cart'][$imgID]['quantity'] to the new value.
$new_qty_list = filter_var($_POST['newqty'],
    FILTER_DEFAULT,
    FILTER_REQUIRE_ARRAY);

foreach ($new_qty_list as $img => $qty) {
    if ($_SESSION['cart'][$img]['quantity'] != $qty) {
        $quantity = (int) $qty;
        if ($quantity <= 0) {
            unset($_SESSION['cart'][$img]);
        } else {
            $_SESSION['cart'][$img]['quantity'] = $quantity;
        }
    }
}

The empty_cart action simply clears the cart from the session and then shows the (now empty) cart view: 

unset($_SESSION['cart']);
include('cart_view.php');

cart_view.php - Displaying the Cart

cart_view.php is responsible for displaying the contents of $_SESSION['cart'], recalculating totals, and providing a UI for updates:

  • If the cart is empty, show a friendly message and a link back to the product list.
  • If the cart has items:
    • Display a table with caption, price, quantity, and line total.
    • Show a Total row at the bottom.
    • Wrap everything in a form with action="cart.php" and action = "update" as a hidden field. 
<?php require 'includes/header.php'; ?>
<main>
    <h2>Your Cart</h2>

    <?php if (empty($_SESSION['cart']) || !isset($_SESSION['cart'])) { ?>
        <h2>There are no products in your cart.</h2>
        <h3>Please use the Purchase Prints link to the left to shop.</h3>
    <?php } else { 
        $total = 0; ?>

        <h4>To remove an item from your cart, change its quantity to 0.</h4>
        <form action="cart.php" method="post">
            <input type="hidden" name="action" value="update">
            <table>
                <tr id="cart_header">
                    <th class="left">Image</th>
                    <th class="right">Price</th>
                    <th class="right">Quantity</th>
                    <th class="right">Total</th>
                </tr>

                <?php foreach ($_SESSION['cart'] as $img => $item) { ?>
                    <tr>
                        <td><?php echo $item['caption']; ?></td>
                        <td class="right">$<?php echo $item['price']; ?></td>
                        <td class="right">
                            <input type="number" class="cart_qty"
                                   name="newqty[<?php echo $img; ?>]"
                                   value="<?php echo $item['quantity']; ?>">
                        </td>
                        <?php
                        if (!isset($item['quantity'])) {
                            $item['quantity'] = 0;
                        }
                        $subtotal = $item['quantity'] * $item['price'];
                        $total   += $subtotal;
                        ?>
                        <td class="right">$<?php echo number_format($subtotal, 2); ?></td>
                    </tr>
                <?php } ?>

                <tr id="cart_footer">
                    <td class="right" colspan="3"><strong>Total:</strong></td>
                    <td class="right"><strong>$<?php echo number_format($total, 2); ?></strong></td>
                </tr>

                <tr>
                    <td></td><td></td>
                    <td><input type="submit" name="submit" value="Update My Cart"></td>
                    <td></td>
                </tr>
            </table>
        </form>

        <p><a href="product_list.php">Add Item</a></p>
        <p><a href="cart.php?action=empty_cart">Empty Cart</a></p>
        <p>Proceed to: <a href="checkout.php">Checkout</a></p>

    <?php } ?>
</main>
<?php include 'includes/footer.php'; ?>

Other Cart Features

Once your cart is working with sessions and forms, you can layer on small convenience features:

  • Add Item - a link back to product_list.php so users can keep shopping.
  • Empty Cart - a link to cart.php?action=empty_cart that clears just the cart data while leaving the user logged in.
  • Checkout - a link to checkout.php that uses the cart totals to build an order.

Behind the scenes, it all comes down to:

  • Using sessions to persist cart state between pages.
  • Using associative arrays to store per-item data (caption, price, quantity).
  • Using HTML forms (with hidden fields & arrays) to add, update, and clear items.

From here, you're ready to connect this with orders, payments, and eventually external APIs for more advanced e-commerce workflows.
