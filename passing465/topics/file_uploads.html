File Uploads

1. Basic Concepts

  • User upload: A visitor selects a file on their computer and sends it to your web server using an HTML form.
  • Three main players:
    • Browser (client): shows the form and sends the file.
    • Web server: receives the file and stores it in a temporary directory.
    • PHP script: validates and processes the file (checks type/size, renames it, resizes if needed, saves info to the database, etc.).
  • MIME (media) types: identify what kind of data a file or response is.
    • Examples: text/html, image/jpeg, image/png, text/css, video/mpeg.
    • They use the format type/subtype, e.g. image/jpeg.
    • Standardized by IANA (Internet Assigned Numbers Authority).
  • Why MIME types matter:
    • In HTTP responses: PHP uses header("Content-Type: ...") to tell the browser what it's sending.
    • In uploads: PHP stores each file's MIME type in $_FILES['something']['type'].
    • In image handling: getimagesize() returns the image's MIME type and dimensions.
  • Images: PHP can inspect images, resize them, create thumbnails, and serve them securely (even if stored outside public_html).
  • If you understand the HTML form, $_FILES, file permissions, image functions, and proxy scripts, you basically own file uploads.

2. HTML & Upload Mechanics

  • Required form attributes:
    • method="post" - file uploads use POST.
    • enctype="multipart/form-data" - tells the browser to send files correctly. Without this, file data is not sent properly.
  • File input element:
<form enctype="multipart/form-data" action="upload_image.php" method="post">
<label for="image">Upload image:</label>
<input type="file" name="image" id="image">
<input type="submit" name="upload" value="Upload">
</form>
  • type="file" creates the “Choose file/Browse” control.
  • The name attribute (e.g. name="image") becomes the key used in $_FILES['image'] in PHP.
  • Optional size limit in HTML:
<input type="hidden" name="MAX_FILE_SIZE" value="3000000">
  • This can help generate specific upload error codes if the file is too large.
  • Basic flow: user picks file > submits form > browser sends request > server temporarily stores the file > PHP processes it.

3. PHP $_FILES

If your HTML has <input type="file" name="site_img">, then PHP gives you a superglobal array:

$_FILES['site_img']['name']      // original filename on user machine
$_FILES['site_img']['type']      // MIME type, e.g. "image/jpeg"
$_FILES['site_img']['size']      // size in bytes
$_FILES['site_img']['tmp_name']  // temporary path on server
$_FILES['site_img']['error']     // error code (0 = OK)
  • Error codes:
    • 0 - No error, upload successful.
    • 1 - File exceeds upload_max_filesize in php.ini.
    • 2 - File exceeds MAX_FILE_SIZE in the HTML form.
    • 3 - File was only partially uploaded.
    • 4 - No file was uploaded.
    • 6 - No temporary folder available.
    • 7 - Unable to write to disk.
    • 8 - File upload stopped.
    • Anything else = system error.
  • Typical pattern: check $_FILES['site_img']['error'] and show a clear message in a switch block like in your sample script.
  • Only if error === 0 do you proceed to validate and move the file.

4. Moving Files & Permissions

  • Moving the uploaded file:
$filename    = $_FILES['site_img']['name'];
$destination = "images/$filename";

if (move_uploaded_file($_FILES['site_img']['tmp_name'], $destination)) {
// Success: file now lives in images/
}
  • move_uploaded_file() is safer than plain copy() for uploads and checks that the source is a valid uploaded file.
  • Unix permission patterns: -rw-rw-r-- shows owner/group/public permissions.
  • Upload destination folders must be writable by the web server user, often using permissions like 777 (rwxrwxrwx), which is why upload folders are a security risk if misused.
  • Public files (HTML/PHP): do not need write for public; they just need read (r).
  • To reduce risk, store user uploads outside of public_html and use PHP to control how they're accessed.

5. Images & Resizing

  • getimagesize(): returns an array with:
    • [0] - width in pixels
    • [1] - height in pixels
    • [2] - integer type code
    • [3] - ready-to-use height="..." width="..." string for an <img> tag
    • ['mime'] - MIME type (e.g. image/jpeg)
  • Scaling to a maximum size (e.g., 350x350):
if ($width <= MAX_SIZE && $height <= MAX_SIZE) {
$ratio = 1;
} elseif ($width > $height) {
$ratio = MAX_SIZE / $width;
} else {
$ratio = MAX_SIZE / $height;
}

$new_w = round($width * $ratio);
$new_h = round($height * $ratio);
  • This keeps the aspect ratio, so the image doesn't look stretched.
  • Creating image resources:
    • imagecreatefromgif(), imagecreatefrompng(), imagecreatefromjpeg() - load the original file.
    • imagecreatetruecolor() - create a new blank image of the target size.
    • imagecopyresampled() - copy and resize with good quality.
    • imagegif(), imagepng(), imagejpeg() - save the resized image to disk.
  • Typical pattern:
    1. Get dimensions and MIME type with getimagesize().
    2. Compute scaling ratio.
    3. Create an image resource from the original.
    4. Create a blank canvas (truecolor).
    5. Use imagecopyresampled() to create the resized copy.
    6. Save the copy to the correct folder (main image and/or thumbnail).

6. Proxy Script & Headers

  • Problem: Uploads stored in /home/usr/uploads are not directly accessible via URL—this is intentional for security.
  • Solution: a PHP proxy script (e.g., show_image.php) that:
    • Finds the requested file.
    • Sends correct HTTP headers (including MIME type and length).
    • Streams the file contents to the browser.
  • Key headers:
$info = getimagesize($image);
$fs   = filesize($image);

header("Content-Type: {$info['mime']}\n");
header("Content-Disposition: inline; filename=\"$name\"\n");
header("Content-Length: $fs\n");
  • Content-Type - tells the browser what kind of file this is (JPEG, PNG, etc.).
  • Content-Disposition: inline - display in the browser. (attachment would force a download.)
  • Content-Length - size in bytes.
  • Important rule: all header() calls must come before any HTML or echoed content.
  • On success, a pure proxy script doesn't output HTML at all- just headers + file data.

7. JavaScript Integration

  • Popup window function: open a popup window sized to each image.
function create_window(image, width, height) {
width  = width + 10;
height = height + 10;

if (window.popup && !window.popup.closed) {
	window.popup.resizeTo(width, height);
}

let specs = "location=no,scrollbars=no,menubar=no,toolbar=no," +
			"resizable=yes,left=0,top=0,width=" + width + ",height=" + height;

let url = "show_image.php?image=" + image;

popup = window.open(url, "ImageWindow", specs);
popup.focus();
}
  • PHP's role: determine each image's filename, width, and height, then output the proper link or event handler that calls create_window().
  • JavaScript's role:
    • Create/resize the popup window.
    • Load the proxy script URL (e.g. show_image.php?image=filename.jpg).
    • Give focus to the popup so the user sees it on top.
  • This shows how front-end JS and back-end PHP cooperate to display secure, dynamic content from user uploads.

8. Security

  • Never trust user uploads: the file could contain malicious content, even if the extension is .jpg.
  • Steganography: hiding malicious code or data inside an image file. Attackers can host "normal-looking" images that actually contain dangerous payloads.
  • Safer storage strategy:
    • Store user uploads outside public_html.
    • Treat admin "site images" differently from untrusted user uploads.
    • Give upload directories carefully controlled permissions (write allowed only where absolutely necessary).
  • Proxy script advantages:
    • Browser never accesses the file directly by path.
    • PHP can enforce rules: must be logged in, must own the file, must be an allowed MIME type, etc.
  • Admin-only maintenance scripts: can:
    • Scan a user's upload folder with scandir().
    • Delete files with unlink() and optionally remove the folder with rmdir().
    • Delete associated records from the database so there are no "orphaned" entries.
