Pagination

Pagination is the process of limiting how many results are displayed on a single page when a list is too long to show all at once. Instead of loading everything, you split the results into pages and provide Next/Previous navigation.

In PHP + MySQL, you use:

  • the query string (for example, ?page=2) to track which page you're on
  • MySQL's LIMIT clause to fetch only that slice of rows
SELECT *
FROM tableName
LIMIT offset, count;

Core Pagination Steps

The basic process looks like this:

  1. Decide how many items you want to display on each page (for example, 6 images).
  2. Count how many total records (or images) are in the database.
  3. Calculate how many pages you'll need in total.
  4. Use LIMIT offset, count so each page only shows its slice of results.

MySQL's LIMIT works like:

  • LIMIT x → returns the first x rows of the result set.
  • LIMIT x, y → skips the first x rows and then returns y rows.

Example:

  • LIMIT 10: rows 1-10
  • LIMIT 10, 10: rows 11-20

JJ Lab Scenario: Paginating Gallery Images

In the JJ gallery lab, there are 8 images in the folder. The requirements:

  • Show no more than 6 images per page.
  • On page 1, show images 1-6 and a Next button.
  • On page 2, show images 7-8, remove Next, and show only Previous.

To make your code work for any page, you calculate the starting image number based on the current page and how many images belong on each page. 

$pageNum    = 1;          // default page
$imgPerPage = 6;          // images per page

$startImg = ($pageNum - 1) * $imgPerPage + 1;

Check the math:

  • Page 1: ($pageNum - 1) * 6 + 1 = 1 > start at image 1
  • Page 2: (2 - 1) * 6 + 1 = 7 > start at image 7
  • If there were 15 images, page 3 would start at image 13

Getting the Current Page from the Query String

The page number is usually passed in the URL like: gallery.php?page=2. You can safely read it like this: 

$pageNum = 1; // default
if (isset($_GET['page']) && is_numeric($_GET['page']) && $_GET['page'] > 0) {
    $pageNum = (int) $_GET['page'];
}

Later, after you know the total number of pages, you can also clamp $pageNum so it doesn't go past the last page.

Counting Total Records & Total Pages

First, count how many images (or rows) exist in the database using COUNT(*):

In code, that looks something like:

$sql  = "SELECT COUNT(*) FROM JJ_images";
$result   = $dbc->query($sql);
$numImages = $result->fetchColumn();

// How many pages total?
$totalPages = ceil($numImages / $imgPerPage);

Now that you know $totalPages, you can ensure the requested page is valid: 

if ($pageNum > $totalPages) {
    $pageNum = $totalPages;
}

Calculating OFFSET for LIMIT

MySQL uses a zero-based offset in LIMIT, so instead of using $startImg directly, you convert it: 

$offset = ($pageNum - 1) * $imgPerPage;

// Then use in your SELECT:
$sql = "SELECT *
        FROM JJ_images
        ORDER BY image_id
        LIMIT $offset, $imgPerPage";

This retrieves only the rows for the current page. For example:

  • Page 1: offset = 0, LIMIT 0, 6 > rows 1-6
  • Page 2: offset = 6, LIMIT 6, 6 > rows 7-12 (or up to however many exist)

Using try...catch with Pagination Queries

Database work should be wrapped in a try...catch to avoid white screen of sadness and show a helpful message instead: 

try {
    $result = $dbc->query($sql);
} catch (PDOException $e) {
    echo $e->getMessage();
}

Then you loop through $result to output each image for the current page.

Previous / Next Page Navigation

The navigation depends on $pageNum and $totalPages:

  • On the first page, show only Next (no Previous).
  • On a middle page, show both Previous and Next.
  • On the last page, show only Previous.
// Previous link
if ($pageNum > 1) {
    $prev = $pageNum - 1;
    echo "<a href='gallery.php?page=$prev'>Previous</a> ";
}

// Next link
if ($pageNum < $totalPages) {
    $next = $pageNum + 1;
    echo "<a href='gallery.php?page=$next'>Next</a>";
}

The goal is to write this logic once so it works for page 1, the last page, and any page in between.

Keeping Table Layout Valid (Blank <td> Cells)

Your gallery images are typically displayed in an HTML table with a fixed number of columns per row (for example, 3 images per row). Valid HTML requires that each row has the same number of <td> cells.

What if there are 9 images and the table displays 3 per row?

  • Rows 1 & 2: 3 images each (perfect)
  • Row 3: only 3rd image might be alone if the math doesn't align

In the JJ lab, when there are fewer images than needed to fill the last row, you output blank cells to keep the table valid: 

$imagesPerRow = 3;
$count       = 0;

echo "<tr>";
foreach ($images as $img) {
    echo "<td>...image html here...</td>";
    $count++;

    if ($count % $imagesPerRow == 0) {
        echo "</tr><tr>";
    }
}

// If the last row isn't full, add empty cells
$remainder = $count % $imagesPerRow;
if ($remainder != 0) {
    $blankCells = $imagesPerRow - $remainder;
    for ($i = 0; $i < $blankCells; $i++) {
        echo "<td>&nbsp;</td>";
    }
    echo "</tr>";
}

This way, your HTML stays valid and your layout stays cute and consistent, even when the last page has only 1-2 images.
